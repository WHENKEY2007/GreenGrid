Project Scope & Objectives
Overview of SquadUp
Enterprise web application that fixes the social gaps in online multiplayer gaming
Players create and join Squad Lobbies ("Looking for Group") built around game title, spoken language, skill level and playstyle
Manage profiles and build friend lists
Receive AI-weighted squad recommendations
Chat in real time across squad lobbies and direct messages
Objectives & Academic Scope
Dual API: RESTful JSON (/api/v1, /api/v2) and SOAP XML web services
Stateless Bearer-token security with ownership guards
Dynamic search using JPA Criteria API and Matrix Variables
Concurrency-safe squad joins with pessimistic locking
Real-time STOMP WebSocket chat and live notifications
AOP for logging, performance timing and audit trails
Built on Spring Boot 3.5 to meet the comprehensive requirements of the API & Micro Services curriculum (241AI024).

Problem Statement & Motivation
Standard matchmaking relies only on skill (MMR) and ping, ignoring whether players are actually compatible.
The Problem
Communication Breakdown:
 players are queued with teammates who do not speak the same language
Playstyle Clashes:
 casual players are paired with hyper-competitive players, creating toxic environments
Social Disconnect:
 teams disband after a single match, so lasting gaming groups are hard to form
The SquadUp Solution
Compatibility-First Matching:
 filter and create squads by game, spoken language and playstyle
Weighted Recommendation Engine:
 compatibility score (%) for open squads based on user preferences
Integrated Social & Chat:
 real-time STOMP chat with automatic profanity moderation, friend management and live notifications

→
JPA / JDBC

→
Database
H2 / MySQL 8
REST Request Flow
Client sends Authorization: Bearer <token>
TokenAuthenticationFilter validates the token
@RestController (Auth, User, Squad, Friend)
@Service layer: transactional logic and AOP
Spring Data JPA (Hibernate) or JdbcTemplate (PlatformStatsDao) reads/writes the database
Other Entry Points
WebSocket / STOMP:
 /ws connection to the WebSocket Controller for chat and live notifications
SOAP:
 client XML request to MessageDispatcherServlet, WSDL at /soap/players.wsdl
Three entry points (REST, SOAP, WebSocket) share one service layer and one database.
